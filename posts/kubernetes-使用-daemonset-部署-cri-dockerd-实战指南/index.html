Kubernetes 使用 DaemonSet 部署 Cri-Dockerd 实战指南

为什么需要 cri-dockerd？

想象一下，Kubernetes (K8s) 是一辆新款的高科技跑车，而 Docker 是你熟悉的老款高性能引擎。从 K8s 1.24 版本开始，这辆跑车为了统一标准（CRI 标准），不再直接支持 Docker 这款引擎了。

但是，很多时候我们还在用 Docker（比如版本 20.10），这时候就需要一个“适配器”来连接 K8s 和 Docker。这个适配器就是 cri-dockerd。

通常我们会在每台机器上像安装软件一样安装 cri-dockerd（使用 systemd）。但今天，我们换个更酷的方法：用 K8s 自己来管理这个适配器，也就是使用 DaemonSet。这就像是派出一队“自动维修工”，确保每台机器上都自动插上了这个适配器。

部署方案

我们将创建一个 DaemonSet，它会在集群的每个节点上启动一个 cri-dockerd 容器。这个容器会做两件事：

  1. 连接 Docker：通过挂载 /var/run/docker.sock，让容器能指挥宿主机上的 Docker。
  2. 暴露接口：生成一个新的 Socket 文件（比如 /etc/cri-dockerd.sock），供 Kubelet 使用。

前置条件

  • 集群节点上已经安装并运行了 Docker (例如 20.10 版本)。
  • 你需要有权限修改 Kubelet 的启动参数（因为光部署好适配器还不够，还得告诉 Kubelet 去插这个新插座）。

apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: cri-dockerd
  namespace: kube-system
  labels:
    k8s-app: cri-dockerd
spec:
  selector:
    matchLabels:
      k8s-app: cri-dockerd
  template:
    metadata:
      labels:
        k8s-app: cri-dockerd
    spec:
      hostNetwork: true
      tolerations:
      - key: node-role.kubernetes.io/master
        effect: NoSchedule
      - key: node-role.kubernetes.io/control-plane
        effect: NoSchedule
      containers:
      - name: cri-dockerd
        # 使用 Mirantis 官方或社区维护的镜像，注意架构匹配
        image: ghcr.io/mirantis/cri-dockerd:v0.3.4 
        command:
        - cri-dockerd
        args:
        # 指定 Docker 的 Socket 路径
        - --docker-endpoint=unix:///var/run/docker.sock
        # 这一点很重要：告诉 cri-dockerd 不要使用 systemd socket 激活，而是直接创建 socket
        # 注意：不同版本的 cri-dockerd 参数可能略有不同，请参考具体版本文档
        - --container-runtime-endpoint=unix:///etc/cri-dockerd/cri-dockerd.sock
        # 指定 CNI 插件位置，通常是 /opt/cni/bin
        - --cni-bin-dir=/opt/cni/bin
        - --cni-conf-dir=/etc/cni/net.d
        # 指定 pause 镜像，根据你的 K8s 版本选择合适的 tag
        - --pod-infra-container-image=registry.k8s.io/pause:3.9
        securityContext:
          privileged: true
        volumeMounts:
        - name: docker-sock
          mountPath: /var/run/docker.sock
        - name: cri-sock-dir
          mountPath: /etc/cri-dockerd
        - name: cni-bin
          mountPath: /opt/cni/bin
        - name: cni-conf
          mountPath: /etc/cni/net.d
      volumes:
      - name: docker-sock
        hostPath:
          path: /var/run/docker.sock
          type: Socket
      - name: cri-sock-dir
        hostPath:
          path: /etc/cri-dockerd
          type: DirectoryOrCreate
      - name: cni-bin
        hostPath:
          path: /opt/cni/bin
      - name: cni-conf
        hostPath:
          path: /etc/cni/net.d

关键配置解析

  1. hostNetwork: true: 使用宿主机网络，这对 CNI 插件正常工作很重要。
  2. privileged: true: 特权模式，必须开启，否则无法完全控制 Docker。
  3. 挂载点:
    • /var/run/docker.sock: 这是 cri-dockerd 指挥 Docker 的遥控器。
    • /etc/cri-dockerd: 这是我们存放新生成的“适配器插口”的地方。

启用步骤

  1. 应用 YAML:

    1

    kubectl apply -f cri-dockerd-ds.yaml

  2. 确认运行状态:

    1

    kubectl get ds -n kube-system cri-dockerd

    确保所有 Pod 都变成了 Running 状态。

  3. 修改 Kubelet 参数 (关键一步): 你需要登录到每个节点，修改 Kubelet 的配置文件或启动参数，将其容器运行时指向我们刚刚创建的 socket。

    编辑 /var/lib/kubelet/kubeadm-flags.env (如果是 kubeadm 安装) 或者 /etc/default/kubelet，添加或修改：

    1

    --container-runtime-endpoint=unix:///etc/cri-dockerd/cri-dockerd.sock

  4. 重启 Kubelet:

    1

    systemctl restart kubelet

常见问题 (Troubleshooting)

  • Socket 找不到: 检查宿主机的 /etc/cri-dockerd/ 目录下是否有 cri-dockerd.sock 文件。如果没有，查看 DaemonSet 的日志：
    1

    kubectl logs -l k8s-app=cri-dockerd -n kube-system
  • CNI 报错: 确保挂载的 /opt/cni/bin 和 /etc/cni/net.d 与宿主机实际路径一致。
  • Cgroup 驱动不一致: 最好确保 Docker (/etc/docker/daemon.json) 和 Kubelet 都配置为使用 systemd 作为 Cgroup 驱动。

小贴士: 虽然 DaemonSet 部署很方便，但生产环境中，直接在宿主机上通过 systemd 安装 cri-dockerd 通常更稳定，因为这样可以避免“容器管理容器”带来的复杂性（比如循环依赖问题）。DaemonSet 方案更适合快速测试或者不方便修改宿主机系统配置的场景。
